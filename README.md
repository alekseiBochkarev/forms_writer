# forms_writer

Автоматическое создание и публикация тестов-викторин в **Яндекс Формах**.

Приложение раз в день генерирует вопросы на общую эрудицию с помощью LLM
(OpenAI-совместимый API), собирает из них тест с правильными ответами,
перемешиванием вариантов и сегментами результатов — и публикует форму.

## Возможности

- Генерация вопросов через любую OpenAI-совместимую модель (`/chat/completions`).
- Создание новой формы **или** добавление вопросов в существующую.
- 4 варианта ответа на вопрос, один правильный, автоматическая пометка верного.
- Все вопросы обязательные (нельзя отправить форму с пропусками).
- Защита от повторов: вопросы прошлых выпусков запоминаются и не повторяются.
- Перемешивание вариантов (`shuffle`).
- Публичный доступ к форме: ссылка открывается у обычных пользователей без авторизации.
- Счётчик в названии формы (`… 2`, `… 3`, …), чтобы не путать выпуски.
- Настройка теста: показ результатов, показ правильных ответов, статистика ответов.
- Сегменты результатов (диапазоны баллов) или порог прохождения.
- Публикация анонса формы в **Telegram** и **VK**.
- Защита от повторной публикации в один день (файл состояния `state.json`).
- Ежедневный запуск через GitHub Actions, а также ручной запуск и `--dry-run`.
- **Фото-тесты** (`python main.py --photo`): выпуск на одну тему с изображениями,
  автоподбор фото из открытых источников и опциональная проверка vision-моделью.

## Структура

```
forms_writer/
├── main.py                  # точка входа и CLI
├── config.py                # загрузка настроек из окружения
├── llm.py                   # генерация вопросов через LLM
├── yandex_forms.py          # клиент API Яндекс Форм
├── publisher.py             # публикация анонса в Telegram и VK
├── dedup.py                 # проверка вопросов на повторы
├── state.py                 # состояние: защита от дублей и список заданных вопросов
├── photo_flow.py            # фото-поток: один выпуск на одну тему
├── photo_sources.py         # поиск изображений (Wikimedia, Openverse и др.)
├── vision.py                # проверка изображений vision-моделью
├── requirements.txt
├── .env.example             # шаблон настроек для локального запуска
├── state.json               # данные о последних публикациях (эрудиция)
├── photo_state.json         # состояние фото-потока (темы, сущности, лицензии)
├── samples/questions.json   # пример готовых вопросов (без LLM)
├── .github/workflows/daily.yml        # ежедневный запуск (эрудиция)
└── .github/workflows/daily_photo.yml  # ежедневный запуск (фото-тесты)
```

## Быстрый старт (локально)

```bash
git clone <ваш-репозиторий>
cd forms_writer
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env   # заполните .env
python main.py --dry-run
python main.py
```

Проверить доступ к API Яндекс Форм и посмотреть свои формы:

```bash
python main.py --check
```

Служебные команды (по id формы):

```bash
python main.py --rename-survey 6aac... --name "Насколько широк ваш кругозор 1"
python main.py --delete-survey 6aac...
```

## Публикация анонса в Telegram и VK

После создания формы приложение публикует короткий анонс со ссылкой.

Публикация включается автоматически, если заданы соответствующие переменные:

- **Telegram:** `TG_BOT_TOKEN` + `TG_TARGET_CHANNEL` (токен бота, добавленного
  администратором в канал).
- **VK:** `VK_ACCESS_TOKEN` + `VK_GROUP_ID` (токен с правом `wall`; id группы —
  положительное число, пост публикуется от имени группы).

Текст анонса настраивается через `ANNOUNCE_TEMPLATE` (одна формулировка) или
`ANNOUNCE_TEMPLATES` (JSON-массив). Доступны подстановки `{name}`, `{count}`,
`{url}`, `{date}`.

Если ничего не задано, используется **встроенный набор формулировок** — при каждом
запуске выбирается случайная, поэтому посты в TG и VK слегка отличаются:

```text
Новый тест: «{name}»

{count} вопросов на разные темы — проверьте свой кругозор.

Пройти: {url}
```

Пример своего списка:

```bash
ANNOUNCE_TEMPLATES=["Вариант А: «{name}» — {url}","Вариант Б ({count} вопросов): {url}"]
```

Если ключи не заданы — публикация в соцсети просто пропускается.

Перед публикацией приложение выставляет форме **публичный доступ** на заполнение
(`POST /surveys/{id}/access` с `action: submit`, `access: public`), поэтому ссылка
вида `https://forms.yandex.ru/u/{id}/` открывается без авторизации у любого
пользователя.

### Сегменты результатов

Если `SEGMENTS` не задан, приложение строит 4 сегмента по четвертям от общего
числа баллов, с разными названиями и описаниями, привязанными к числу верных
ответов, например для 13 вопросов:

- `0–3` — «Начинающий»
- `4–6` — «Любознательный»
- `7–9` — «Эрудит»
- `10–13` — «Ходячая энциклопедия»

В админке Яндекс Форм нижняя граница сегмента отображается как «предыдущая + 0,01»
(это внутренний формат сервиса); фактические границы указаны в описании.

## Защита от дублей и повторов вопросов

Приложение хранит в `state.json` дату последней публикации и список уже заданных
вопросов (`asked_questions`).

- Если запуск повторяется в тот же день (например, резервным расписанием),
  форма не создаётся заново. Для принудительного запуска — `--force` или `FORCE=true`.
- Перед генерацией список прошлых вопросов передаётся модели с требованием не
  повторяться, а после генерации вопросы дополнительно проверяются на совпадения
  (точные и похожие формулировки). Повторы отбрасываются и генерируются заново.

Список хранит последние 500 вопросов, поэтому защита работает и спустя много выпусков.

## Фото-тесты

Отдельный поток выпускает тест, в котором каждый вопрос сопровождается фотографией.
Каждый выпуск посвящён **одной теме** (например «советские фильмы» или «актёры»),
формулировка у всех вопросов общая:

- темы про фильмы → «Кадр из какого фильма?»;
- темы про актёров → «Кто на фото?»;
- остальные темы → «Что (кто) изображено на фотографии?».

У каждого вопроса 4 варианта: один верный и три дистрактора **строго того же класса**
(их генерирует LLM). Подсказки (год, режиссёр и т.п.) не добавляются.

### Запуск

```bash
# фото-поток включается переменной PHOTO_FLOW_ENABLED=true
python main.py --photo                              # тема выбирается случайно
python main.py --photo --photo-theme "советские фильмы"
python main.py --photo --dry-run                    # показать план без публикации
python main.py --photo --force                       # игнорировать защиту от дублей
```

В `--dry-run` приложение генерирует сущности и варианты через LLM, показывает
найденные URL кандидатов, но **не скачивает изображения, не обращается к Яндекс
Формам и не проверяет фото через vision** (это явно пишется в лог). Состояние не
обновляется.

### Откуда берутся фото

По умолчанию включены открытые источники `wikimedia` (Wikimedia Commons) и
`openverse` (Openverse). Дополнительно можно включить кино-источники
(`FILM_RU_ENABLED`, `FILM_GRAB_ENABLED`, `MOVIE_SCREENCAPS_ENABLED`) — по умолчанию
они **выключены**, так как их права/лицензии рискованнее.

Для Wikimedia обязателен описательный `WIKIMEDIA_USER_AGENT`: если источник активен,
а переменная не задана, приложение выводит предупреждение (но не падает).

Автор и лицензия каждого использованного изображения сохраняются **только** в
`photo_state.json` (поле `images` в записи выпуска) и не попадают ни в форму, ни в
анонс.

### Проверка изображений (vision)

Проверка того, что на фото действительно нужная сущность, выполняет vision-модель
(OpenAI-совместимый API с поддержкой изображений). По умолчанию она **выключена**
(`PHOTO_VISION_ENABLED=false`): тогда изображения используются без проверки и сеть
для vision не дёргается. При включении проверка выполняется по каждому кандидату;
если vision недоступна, кандидат считается пригодным, чтобы не терять выпуск из-за
инфраструктурных сбоев.

Число вопросов задаётся `PHOTO_QUESTIONS_COUNT` (по умолчанию 10). Если удалось
подготовить меньше `PHOTO_MIN_QUESTIONS` (по умолчанию равно числу вопросов),
выпуск не публикуется. Название формы — `PHOTO_SURVEY_NAME` с уточнением темы,
например «Что на фото? Советские фильмы»; нумерация форм отдельная от эрудиции.

Состояние фото-потока хранится отдельно — в `photo_state.json`: дата последней
публикации, список выпусков, использованные темы и сущности (чтобы не повторяться).
Анонс публикуется теми же шаблонами, что и для эрудиции (`ANNOUNCE_TEMPLATES`).

## Как получить токен и org id

1. **Токен Яндекс Форм.** Создайте OAuth-приложение на <https://oauth.yandex.ru>
   («Для доступа к API или отладки»), добавьте доступ
   **«Изменение настроек форм (forms:write)»**, затем откройте
   `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>`
   и скопируйте токен.
2. **Org id.** В Яндекс Трекере: `https://tracker.yandex.ru/admin/orgs` →
   значение поля «Идентификатор». Для Yandex Identity Hub используйте
   `YANDEX_ORG_ID` как Cloud Org ID и заголовок `X-Cloud-Org-Id`.
3. API Яндекс Форм доступно для **«Форм для бизнеса» (Яндекс 360)**.

## Ежедневный запуск в GitHub Actions

1. Запушьте проект в репозиторий.
2. **Settings → Secrets and variables → Actions**:
   - **Secrets:** `LLM_API_KEY`, `YANDEX_FORMS_TOKEN`, `YANDEX_ORG_ID`
     и, для соцсетей, `TG_BOT_TOKEN`, `TG_TARGET_CHANNEL`,
     `VK_ACCESS_TOKEN`, `VK_GROUP_ID`;
   - **Variables** (необязательно): `LLM_BASE_URL`, `LLM_MODEL`,
     `QUESTIONS_TOPIC`, `QUESTIONS_COUNT`, `QUESTIONS_LANGUAGE`.
3. Расписание задаётся в `.github/workflows/daily.yml` (cron в UTC: основной
   `0 6 * * *` и резервный `30 6 * * *`). Запустить можно и вручную:
   вкладка **Actions → Daily form → Run workflow**.
4. Workflow сам коммитит обновлённый `state.json` (нужны права
   `permissions: contents: write`, они уже указаны).

Фото-тесты запускаются отдельным workflow `.github/workflows/daily_photo.yml`
(шаблон `Daily photo form`) по cron `0 16 * * *` и `30 16 * * *` (UTC), то есть
примерно на 10 часов позже эрудиционного выпуска. Он выполняет
`python main.py --photo` и коммитит только `photo_state.json` (перед push делает
`git pull --rebase`). Запустить вручную: **Actions → Daily photo form → Run workflow**.

## Безопасность

- Не коммитьте `.env` и не храните токены в коде — используйте секреты GitHub.
- Выдавайте токену минимально необходимый доступ (`forms:write`) и отзывайте его,
  когда он больше не нужен.
- Токен даёт полный доступ ко всем вашим формам — обращайтесь с ним аккуратно.

## Ограничения

- API Яндекс Форм работает только для форм в составе организации (Яндекс 360).
- Генерация вопросов требует доступа к LLM API; при недоступности используйте
  `QUESTIONS_FILE` с заготовкой.
